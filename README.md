# Хэсэг A — Category-Partition

## A1. Сонголт ба төлөөлөх утгууд

Шалгах функц: `POST /transfer`

Оролтын бүтэц:
`{"from": ID, "to": ID, "amount": NUM, "currency": CODE}`

### Параметрийн сонголтууд

| Параметр | Сонголт (Category) | Төлөөлөх утга (Choice) | Тайлбар |
|---|---|---|---|
| from | Дансны оршин байгаа эсэх | Valid | Данс бүртгэлтэй, царцаагдаагүй |
| from | Дансны төлөв | Frozen | Данс бүртгэлтэй боловч царцаагдсан |
| from | Дансны оршин байгаа эсэх | Missing | Данс олдохгүй |
| to | Хүлээн авагчийн данс | Valid | Бүртгэлтэй, шилжүүлэгчээс өөр данс |
| to | Хүлээн авагчийн данс | Missing | Хүлээн авагчийн данс олдохгүй |
| to | Дансны хамаарал | SameAsFrom | Шилжүүлэгч ба хүлээн авагч ижил |
| amount | Шилжүүлгийн хэмжээ | Normal | Тэгээс их, үлдэгдэл ба лимитэд багтана |
| amount | Шилжүүлгийн хэмжээ | Zero | Хэмжээ тэгтэй тэнцүү |
| amount | Шилжүүлгийн хэмжээ | Negative | Хэмжээ тэгээс бага |
| amount | Үлдэгдэл | OverBalance | Хөрвүүлсний дараах дүн үлдэгдлээс их |
| amount | Өдрийн лимит | OverLimit | Хөрвүүлсний дараах дүн лимитээс их |
| currency | Валютын хамаарал | Same | Дансны валюттай ижил |
| currency | Валютын хамаарал | Different | Дансны валютаас өөр, хөрвүүлэлт шаардлагатай |

### Далд орчны сонголтууд

| Орчны сонголт | Төлөөлөх утгууд | Нөлөө |
|---|---|---|
| Шилжүүлэгчийн үлдэгдэл | Хангалттай / Хангалтгүй | Шилжүүлэг зөвшөөрөгдөх эсэхэд нөлөөлнө |
| Өдрийн лимитийн үлдэгдэл | Хангалттай / Хүрэлцэхгүй | Лимит хэтэрсэн эсэхийг тодорхойлно |
| Валют хөрвүүлэлт | Хөрвүүлэлт шаардлагагүй / Шаардлагатай | Үлдэгдэл ба лимитийг шалгах дүнд нөлөөлнө |

Тайлбар: `Normal` нь тухайн дансны үлдэгдэл болон өдрийн лимитэд багтах хүчинтэй дүнг илэрхийлнэ. `OverBalance`, `OverLimit` нь валют хөрвүүлсний дараах дүнгээр тодорхойлогдоно. Тодорхойлолтод валютын код буруу байх үеийн алдааны төрөл заагаагүй тул энэ лабораторид тусгай oracle зохиож нэмээгүй.


## A2. Хязгаарлалт ба хамаарал

| Тэмдэглэгээ | Нөхцөл | Үндэслэл |
|---|---|---|
| [ERROR] | `from=Missing` үед `from=Frozen` сонголтыг хамтад нь авч үзэхгүй | Олдохгүй дансны төлөвийг шалгах боломжгүй |
| [ERROR] | `to=Missing` үед хүлээн авагчийн дансны төлөв шалгахгүй | Данс олдоогүй үед дансны төлөв тодорхойгүй |
| [ERROR] | `amount=Zero` эсвэл `amount=Negative` үед шилжүүлэг амжилтгүй | Шилжүүлгийн дүн эерэг байх ёстой |
| [ERROR] | `from=Frozen` үед шилжүүлэг амжилтгүй | Царцаасан данснаас шилжүүлэхийг хориглоно |
| [ERROR] | `to=SameAsFrom` үед шилжүүлэг амжилтгүй | Өөрийн данс руу шилжүүлэхийг хориглосон гэж үзэв |
| [ERROR] | `amount=OverBalance` үед шилжүүлэг амжилтгүй | Үлдэгдэл хүрэлцэхгүй |
| [ERROR] | `amount=OverLimit` үед шилжүүлэг амжилтгүй | Өдрийн лимит хэтэрсэн |
| [IF] | `currency=Different` үед валют хөрвүүлэлтийн дараах дүнгээр үлдэгдэл, лимитийг шалгана | Валютын ханш шилжүүлэх дүнд нөлөөлнө |
| [SINGLE] | Нэг тестэд `from` дансны оршин байгаа эсэхийг нэг л утгаар сонгоно | Нэг данс нэгэн зэрэг байгаа ба байхгүй байж болохгүй |
| [SINGLE] | Нэг тестэд `amount`-ын ангиллыг нэг л утгаар сонгоно | Дүн нэгэн зэрэг тэг, сөрөг, хэвийн байж болохгүй |

Тайлбар: Эдгээр хязгаарлалт нь лабораторийн загварчлалд ашигласан таамаглал юм. Бодит системийн шаардлага өөр бол тухайн шаардлагад нийцүүлэн өөрчилнө.

## A3. N → M тооцоо

Browser загварын параметрийн бүрэн хослолын тоо:
N = 3 × 3 × 2 × 2 × 2 × 2 = 144.

PICT-ийн pairwise үр дүн нь 10 тест кейс, гурван хүчин зүйлийн
хамрах хүрээтэй үр дүн нь 20 тест кейс байна.
Иймээс pairwise загварчлал бүрэн хослолтой харьцуулахад
туршилтын тоог 144-өөс 10 болгон бууруулсан.

Transfer загварт From, To, Amount, Currency гэсэн дөрвөн
параметр байна. Negative ангиллыг оруулсны дараа бүрэн
хослолын тоо N = 3 × 3 × 5 × 2 = 90 болно.
Хязгаарлалтгүй загварын бодит тестийн тоо M нь
results/transfer-nc.txt файлын толгой мөрөөс бусад мөрийн тоо юм.
Хязгаарлалттай загварын M утгыг results/transfer.txt-ээс авна.
N → M нь бүрэн хослолын тооноос PICT-ийн үүсгэсэн
тестийн тоо руу шилжсэнийг харуулна.
IF нөхцөлөөр хүчингүй хослолууд хасагдах тул
хязгаарлалттай ба хязгаарлалтгүй загварын M ялгаатай байна.

## A4. Тестийн спецификац ба хүлээгдэх үр дүн

Дараах хүснэгт нь Category-Partition загварын үндсэн
таамаглал дээр үндэслэсэн тестийн спецификац юм.
Бодит API ажиллуулж баталгаажуулсан үр дүн биш.

| ID | Setup | Оролтын ангилал | Хүлээгдэх үр дүн |
|---|---|---|---|
| T01 | Хоёр данс хүчинтэй, үлдэгдэл хүрэлцээтэй | Valid, Valid, Normal, Same | Шилжүүлэг амжилттай |
| T02 | Шилжүүлэгчийн данс царцаалттай | Frozen, Valid, Normal, Same | Дансны төлөвийн алдаа |
| T03 | Шилжүүлэгчийн данс олдохгүй | Missing, Valid, Normal, Same | Шилжүүлэгчийн дансны алдаа |
| T04 | Хүлээн авагчийн данс олдохгүй | Valid, Missing, Normal, Same | Хүлээн авагчийн дансны алдаа |
| T05 | Хоёр данс ижил | Valid, SameAsFrom, Normal, Same | Ижил дансны алдаа |
| T06 | Шилжүүлгийн дүн тэг | Valid, Valid, Zero, Same | Дүнгийн алдаа |
| T07 | Шилжүүлгийн дүн сөрөг | Valid, Valid, Negative, Same | Дүнгийн алдаа |
| T08 | Үлдэгдэл хүрэлцэхгүй | Valid, Valid, OverBalance, Same | Үлдэгдлийн алдаа |
| T09 | Өдрийн лимит хэтэрсэн | Valid, Valid, OverLimit, Same | Лимитийн алдаа |
| T10 | Валют хөрвүүлэлт шаардлагатай | Valid, Valid, Normal, Different | Ханш тооцож, амжилттай шилжүүлэх |
| T11 | Данс царцаалттай бөгөөд дүн тэг | Frozen, Valid, Zero, Same | Тогтоосон алдааны эрэмбээр нэг үндсэн алдаа |
| T12 | Данс олдохгүй бөгөөд валют өөр | Missing, Valid, Normal, Different | Дансны алдаа |
| T13 | Хүлээн авагч олдохгүй бөгөөд дүн сөрөг | Valid, Missing, Negative, Same | Хүлээн авагчийн алдаа |
| T14 | Үлдэгдэл хүрэлцэхгүй, валют өөр | Valid, Valid, OverBalance, Different | Хөрвүүлэлтийн дараах үлдэгдлийн алдаа |

T07, T13 зэрэг жишээг PICT загварын IF нөхцөлтэй
нийцүүлэн сонгох шаардлагатай. Загварт зөвшөөрөөгүй
хослолыг бодит PICT гаралт гэж тайлагнаж болохгүй.

### Олон алдааны давуу эрэмбэ

Энэ лабораторийн таамаглалд алдааг дараах дарааллаар
ангилна: эхлээд шилжүүлэгчийн данс олдох эсэх,
дараа нь хүлээн авагчийн данс олдох эсэх, дараа нь
шилжүүлэгчийн дансны төлөв, дараа нь хоёр дансны
хамаарал, дараа нь дүнгийн эерэг эсэх, үлдэгдэл,
өдрийн лимитийн шалгалт. Валютын хөрвүүлэлтийг
үлдэгдэл болон лимитийн шалгалтын өмнө хийнэ.
Бодит системийн шаардлага өөр бол энэ эрэмбийг өөрчилнө.

## B1. PICT загвар ба үр дүн

- browser.model: browser тохиргооны pairwise болон 3-way загвар.
- transfer-nc.model: шилжүүлгийн хязгаарлалтгүй ангиллын загвар.
- transfer.model: IF нөхцөлтэй шилжүүлгийн загвар.
- transfer-neg.model: сөрөг тестийн загвар.
- results/*.txt: PICT-ийн ажиллуулсан гаралт.

Хэрэглээний нотолгоо results/pict-build.txt файлд хадгалагдана.
PICT-ийн эх кодыг энэ репод оруулахгүй.

## B2. Бодит тест кейс болгох

PICT-ийн мөрийг бодит тест болгохдоо:
1. Setup буюу данс, үлдэгдэл, лимит, валютын нөхцөлийг тогтооно.
2. Оролтыг POST /transfer хүсэлт болгон өгнө.
3. Хариуны статус, алдааны код болон дансны үлдэгдлийн өөрчлөлтийг шалгана.
4. Бодит системийн хариуг тэмдэглэж, хүлээгдэж буй үр дүнтэй харьцуулна.

Happy path тестэд хоёр хүчинтэй данс, хангалттай үлдэгдэл,
лимит болон зөв дүн ашиглана. Negative тестэд transfer-neg
гаралтаас сонгосон нэг сөрөг нөхцөлийг setup болон oracle-той
холбож баримтжуулна.

## B3. Greedy алгоритмын тайлбар ба дүгнэлт

PICT нь параметрүүдийн боломжит утгуудын хослолыг загварчилдаг.
Pairwise тест нь параметр бүрийн утгын хосуудыг хамруулах зорилготой.
3-way тест нь гурван параметрийн утгын хослолыг хамруулдаг.
Greedy арга нь нэг алхамд хамрагдаагүй олон хослолыг хамруулах
тестийн мөрийг сонгох замаар тестийн тоог багасгахад ашиглагддаг.
Энэ арга нь бүрэн Cartesian product үүсгэхээс цөөн тестээр
олон хослолыг хамруулах боломж олгодог.
Гэхдээ цөөн тест үүссэн нь бүх бизнесийн алдаа илэрсэн гэсэн үг биш.
IF нөхцөл нь боломжгүй эсвэл шаардлагаар хориглосон хослолыг хасна.
Negative загварын мөрүүдийг setup, оролт, oracle-той холбож шалгах хэрэгтэй.
Иймээс PICT-ийн гаралтыг бодит системийн баталгаажуулалттай
хослуулж байж тестийн үр дүнгийн талаар дүгнэлт хийнэ.

## B4. Үр дүнгийн тоог шалгах

Тестийн тоо нь тухайн results/*.txt файлын эхний толгой мөрийг
хассан мөрийн тоотой таарч байх ёстой. Загвар өөрчлөгдөх бүрд
PICT-ийг дахин ажиллуулж, README-д тэмдэглэсэн тоонуудыг
шинэ гаралттай тулгана.
