# Хэсэг A — Category-Partition

## A1. Сонголт ба төлөөлөх утгууд

Шалгах функц: `POST /transfer`

Оролтын бүтэц: `{"from": ID, "to": ID, "amount": NUM, "currency": CODE}`

| Параметр | Category | Choice | Тайлбар |
|---|---|---|---|
| from | Дансны оршин байгаа эсэх | Valid | Бүртгэлтэй, царцаагдаагүй данс |
| from | Дансны төлөв | Frozen | Бүртгэлтэй боловч царцаагдсан данс |
| from | Дансны оршин байгаа эсэх | Missing | Олдохгүй данс |
| to | Хүлээн авагч | Valid | Бүртгэлтэй, өөр данс |
| to | Хүлээн авагч | Missing | Олдохгүй данс |
| to | Дансны хамаарал | SameAsFrom | Шилжүүлэгчтэй ижил данс |
| amount | Шилжүүлгийн хэмжээ | Normal | Эерэг, үлдэгдэл болон лимитэд багтана |
| amount | Шилжүүлгийн хэмжээ | Zero | Тэг дүн |
| amount | Шилжүүлгийн хэмжээ | Negative | Сөрөг дүн |
| amount | Үлдэгдэл | OverBalance | Хөрвүүлсний дараах дүн үлдэгдлээс их |
| amount | Өдрийн лимит | OverLimit | Хөрвүүлсний дараах дүн лимитээс их |
| currency | Валютын хамаарал | Same | Дансны валюттай ижил |
| currency | Валютын хамаарал | Different | Хөрвүүлэлт шаардлагатай |

### Далд орчны сонголтууд

| Орчны сонголт | Төлөөлөх утгууд | Нөлөө |
|---|---|---|
| Дансны үлдэгдэл | Хангалттай / Хангалтгүй | Шилжүүлэг зөвшөөрөгдөх эсэх |
| Өдрийн лимит | Хангалттай / Хэтэрсэн | Лимитийн шалгалт |
| Валют хөрвүүлэлт | Шаардлагагүй / Шаардлагатай | Шалгах дүн өөрчлөгдөх эсэх |

`Normal` нь эерэг бөгөөд үлдэгдэл, лимитэд багтах дүнг илэрхийлнэ. `OverBalance` болон `OverLimit` нь хөрвүүлсний дараах дүнгээр тодорхойлогдоно.

## A2. Хязгаарлалт ба N → M тооцоо

| Төрөл | Нөхцөл | Үндэслэл |
|---|---|---|
| ERROR | `from=Missing` | Эх данс байхгүй тул шилжүүлэг амжилтгүй |
| ERROR | `from=Frozen` | Царцаасан данснаас шилжүүлэхийг хориглоно |
| ERROR | `to=Missing` | Хүлээн авагчийн данс байхгүй |
| ERROR | `to=SameAsFrom` | Өөрийн данс руу шилжүүлэхийг хориглоно |
| ERROR | `amount=Zero` эсвэл `Negative` | Шилжүүлгийн дүн эерэг байх ёстой |
| ERROR | `amount=OverBalance` | Үлдэгдэл хүрэлцэхгүй |
| ERROR | `amount=OverLimit` | Өдрийн лимит хэтэрсэн |
| IF | `currency=Different` | Үлдэгдэл болон лимитийг хөрвүүлсний дараа шалгана |
| SINGLE | `from` нэг л сонголттой | Нэг данс нэг тестэд байхгүй, царцаасан, хүчинтэй гэсэн утгуудыг зэрэг авахгүй |
| SINGLE | `amount` нэг л ангилалтай | Дүн нэгэн зэрэг хэвийн, тэг, сөрөг байж болохгүй |

PICT загварт `Amount` нь `Zero`, `Normal`, `OverBalance`, `OverLimit` гэсэн дөрвөн утгатай. `Negative`-ийг гараар хийсэн спецификацид тусад нь авч үзсэн.

Хязгаарлалтгүй загварын бүрэн комбинацийн тоо:

`N = 3 × 3 × 4 × 2 = 72`

`From=Missing` үед `Amount=Normal` байх ёстой. `To=Missing` үед мөн `Amount=Normal` байх ёстой.

- `From=Missing` үед зөвшөөрөгдөх комбинац: `1 × 3 × 1 × 2 = 6`.
- `From≠Missing`, `To=Missing` үед: `2 × 1 × 1 × 2 = 4`.
- `From≠Missing`, `To≠Missing` үед: `2 × 2 × 4 × 2 = 32`.

Иймээс хязгаарлалтыг хангасан бүрэн комбинацийн тоо `M = 6 + 4 + 32 = 42`.

**Бүрэн комбинацийн тоо: 72 → 42.** PICT-ийн greedy аргаар гаргасан бодит тестийн мөрийн тоо нь бүрэн комбинацийн тоотой адил биш.

## A3. Спецификацийн хүснэгт

Давхар алдаатай үед ашиглах тестийн хүлээгдэх үр дүнгийн давуу эрэмбийг дараах байдлаар тогтоов: эх данс байхгүй → эх данс царцаасан → хүлээн авагч байхгүй → ижил данс → буруу дүн → үлдэгдэл хүрэлцэхгүй → лимит хэтэрсэн. Энэ эрэмбэ нь тодорхойлолтод заагаагүй тул лабораторийн тестийн загварт ашигласан таамаглал юм.

| № | From | To | Amount | Currency | Хүлээгдэх үр дүн |
|---|---|---|---|---|---|
| 1 | Valid | Valid | Normal | Same | `201 {"result":"OK"}` |
| 2 | Missing | Valid | Normal | Same | `200 ERROR_NO_FROM` |
| 3 | Frozen | Valid | Normal | Same | `200 ERROR_FROZEN` |
| 4 | Valid | Missing | Normal | Same | `200 ERROR_NO_TO` |
| 5 | Valid | SameAsFrom | Normal | Same | `200 ERROR_SAME_ACCOUNT` |
| 6 | Valid | Valid | Zero | Same | `200 ERROR_BAD_AMOUNT` |
| 7 | Valid | Valid | Negative | Same | `200 ERROR_BAD_AMOUNT` |
| 8 | Valid | Valid | OverBalance | Same | `200 ERROR_INSUFFICIENT` |
| 9 | Valid | Valid | OverLimit | Same | `200 ERROR_LIMIT` |
| 10 | Valid | Valid | Normal | Different | `201 {"result":"OK"}`; хөрвүүлэлт зөв |
| 11 | Frozen | Valid | OverBalance | Same | `200 ERROR_FROZEN` |
| 12 | Valid | Missing | OverLimit | Same | `200 ERROR_NO_TO` |
| 13 | Missing | Missing | Normal | Same | `200 ERROR_NO_FROM` |
| 14 | Valid | SameAsFrom | Zero | Different | `200 ERROR_SAME_ACCOUNT` |

Энд `200` нь тодорхойлолтод өгсөн оролтын алдааны HTTP статусыг, `201` нь амжилтын статусыг илэрхийлнэ. Олон алдааны давуу эрэмбийг бодит системийн кодоор баталгаажуулаагүй.

# Хэсэг B — Microsoft PICT

## B1. Browser загвар

Бүрэн комбинацийн тоо: `3 × 3 × 2 × 2 × 2 × 2 = 144`.

| Үр дүн | Тестийн мөр | Харьцуулалт |
|---|---:|---|
| Browser 2-way | 10 | Бүрэн 144 комбинацаас цөөн |
| Browser 3-way | 20 | Бүрэн 144 комбинацаас цөөн |

PICT-ийн 2-way гаралт нь бүх параметрийн хос утгын хамралтыг хангах зорилготой. Greedy алгоритм тухайн алхамд олон шинэ хосыг хамрах мөрийг сонгодог учраас хамгийн цөөн мөртэй шийдлийг заавал олохгүй. 3-way загвар нь гурван параметрийн утгын бүх боломжит хослолыг хамруулах шаардлагатай тул илүү олон тестийн мөр үүсгэдэг.

## B2. Шилжүүлгийн загваруудын харьцуулалт

| Загвар | Үр дүнгийн файл | Тестийн мөр |
|---|---|---:|
| Browser 2-way | `results/browser-2way.txt` | 10 |
| Browser 3-way | `results/browser-3way.txt` | 20 |
| Transfer, хязгаарлалтгүй | `results/transfer-nc.txt` | 13 |
| Transfer, IF хязгаарлалттай | `results/transfer.txt` | 12 |
| Transfer 2-way | `results/transfer-2way.txt` | 12 |
| Transfer 3-way | `results/transfer-3way.txt` | 26 |
| Transfer negative | `results/transfer-neg.txt` | 16 |
| Transfer negative 3-way | `results/transfer-neg-3way.txt` | 16 |

Мөрийн тоо нь файлын эхний толгой мөрийг хассан тоо юм. Хязгаарлалттай `transfer.model` нь зарим комбинацыг хориглодог тул хязгаарлалтгүй загвараас ялгаатай үр дүн гарна. `transfer-neg.model` загварын `~` тэмдэглэгээ нь сөрөг утгуудыг илэрхийлж, нэг мөрөнд олон сөрөг утга давхар орохоос сэргийлдэг. Загваруудын бодит тоог дараах шалгах командаар дахин баталгаажуулна.

```bash
for f in results/browser-2way.txt results/browser-3way.txt \
         results/transfer-nc.txt results/transfer.txt \
         results/transfer-2way.txt results/transfer-3way.txt \
         results/transfer-neg.txt results/transfer-neg-3way.txt
do
    printf '%s: ' "$f"
    awk 'NR>1 {n++} END {print n+0}' "$f"
done
```

## B3. PICT гаралтаас бодит тест кейс үүсгэх

| № | Эх сурвалжийн мөр | Setup | Оролт | Хүлээгдэх үр дүн |
|---|---|---|---|---|
| 1 | `transfer-neg.txt`: `Valid Valid Normal Same` | Эх данс царцаагдаагүй, үлдэгдэл болон лимит хангалттай; хоёр данс өөр | `{"from":"A001","to":"B001","amount":100,"currency":"MNT"}` | `201 {"result":"OK"}` |
| 2 | `transfer-neg.txt`: `Valid Valid ~Zero Same` | Хоёр данс хүчинтэй, эх дансны үлдэгдэл хангалттай | `{"from":"A001","to":"B001","amount":0,"currency":"MNT"}` | `200 ERROR_BAD_AMOUNT` |
| 3 | `transfer-neg.txt`: `~Frozen Valid Normal Same` | Эх данс царцаасан, хүлээн авагч хүчинтэй | `{"from":"A001","to":"B001","amount":100,"currency":"MNT"}` | `200 ERROR_FROZEN` |

Дээрх `A001`, `B001` нь тестийн setup-д зориулсан жишээ ID бөгөөд бодит системийн дансны ID гэж үзэхгүй. `transfer-neg.txt`-ийн эхний мөр нь happy path, дараагийн мөрүүд нь нэг сөрөг нөхцөлтэй тестүүд юм. Эдгээр oracle нь өгөгдсөн функцийн тодорхойлолт болон дээр тогтоосон алдааны давуу эрэмбэд үндэслэсэн.

## B4. Greedy алгоритмын тайлбар ба дүгнэлт

PICT нь pairwise болон higher-way тестийн комбинацыг greedy аргаар үүсгэдэг. Алгоритм алхам бүрд хамрагдаагүй олон хосыг хамруулах боломжтой мөрийг сонгодог. Энэ нь бүх комбинацыг туршихаас цөөн тестээр параметрүүдийн хамрах хүрээг нэмэгдүүлдэг. Гэхдээ greedy алгоритм нь заавал хамгийн цөөн мөртэй шийдлийг олох баталгаа биш. Browser загварын 2-way гаралт 10 мөр, 3-way гаралт 20 мөр болсон. Transfer загварт IF хязгаарлалт тавихад боломжгүй гэж үзсэн комбинацууд хасагдаж, гаралтын мөрийн тоо өөрчлөгдсөн. Negative загвар нь алдааны утгуудыг `~` тэмдэглэгээгээр ялгаж, нэг мөрөнд олон алдааны нөхцөл давхардахаас сэргийлдэг. Category-Partition арга нь алдааны семантик, хязгаарлалт, хүлээгдэх үр дүнг хүнээр тодорхойлоход илүү тохиромжтой. PICT нь параметрүүдийн хос болон гурвалсан хамралтыг системтэйгээр гаргахад ашигтай. Иймээс хоёр аргыг хамтад нь ашиглах нь тестийн логик болон комбинацийн хамралтыг сайжруулна.

## Нийт дүгнэлт

Энэ лабораторид Category-Partition аргаар шилжүүлгийн параметр, төлөөлөх утга болон хязгаарлалтыг тодорхойлсон. Дараа нь PICT ашиглан хязгаарлалтгүй, хязгаарлалттай, negative болон browser загварын тестийн мөрүүдийг үүсгэсэн. Бүрэн комбинацийн тоо ба PICT-ийн гаралтын мөрийн тоо өөр ойлголт болохыг харьцуулалтаар харуулсан. Хязгаарлалт нь боломжгүй комбинацыг хасдаг бол negative тэмдэглэгээ нь алдаатай сонголтуудыг тестийн мөрүүдэд зохистой тусгаарлахад тусалдаг. PICT-ийн гаралт дангаараа хүлээгдэх үр дүнг тодорхойлохгүй тул бодит тест кейсэд setup, оролт, oracle нэмэх шаардлагатай. Давхар алдааны үед аль алдааг түрүүлж буцаахыг лабораторийн таамаглалаар тогтоосон. Greedy алгоритм нь үр дүнтэй боловч хамгийн цөөн тестийн мөрийг заавал гаргахгүй. Гар аргаар тодорхойлсон спецификаци нь бизнесийн дүрэм, алдааны утгыг илүү тодорхой харуулдаг. Эдгээр аргыг хослуулснаар тестийн загварчлал болон комбинацийн хамралтыг нэгэн зэрэг үнэлэх боломжтой.
### B5. Хязгаарлалт, сөрөг утга ба greedy гаралтын харьцуулалт

| Хувилбар | Файл | Тестийн мөр |
|---|---|---:|
| Хязгаарлалтгүй transfer | `results/transfer-nc.txt` | 13 |
| IF хязгаарлалттай transfer | `results/transfer.txt` | 12 |
| Сөрөг утгатай transfer | `results/transfer-neg.txt` | 16 |

Мөрийн тоонд эхний толгой мөрийг оруулаагүй. Эдгээр тоог PICT-ийн бодит гаралттай дахин тулгаж, зөрүү гарвал README болон үр дүнгийн файлыг хамтад нь шинэчилнэ.

Хязгаарлалтгүй загвар нь параметрүүдийн утгуудыг IF нөхцөлөөр хязгаарлахгүй тул илүү олон хослолыг авч үздэг. IF хязгаарлалттай загвар нь эх данс эсвэл хүлээн авагч байхгүй үед шилжүүлгийн дүнг `Normal` байхаар хязгаарладаг. Negative загварт `~` тэмдэглэгээгээр алдаатай утгуудыг тэмдэглэснээр нэг тестийн мөрөнд олон сөрөг нөхцөл зэрэг орох эрсдэлийг бууруулдаг. Энэ нь бодит системийн бүх алдааны давуу эрэмбийг автоматаар тогтоохгүй тул олон алдаатай нөхцөлийн oracle-ийг тусад нь тодорхойлох шаардлагатай.

`transfer-neg.txt` файлд `Valid / Valid / Normal / Same` болон `Valid / Valid / Normal / Different` гэсэн happy path-д тохирох хоёр мөр байна. Гэхдээ бодит амжилтын үр дүнг шалгахын тулд дансны setup, үлдэгдэл, өдрийн лимит, валютын ханшийг зөв тохируулна. Greedy алгоритм нь тухайн алхамд олон шинэ хосыг хамруулах мөрийг сонгодог боловч глобал хамгийн цөөн мөртэй шийдлийг заавал олдоггүй. Иймээс pairwise болон 3-way гаралтын мөрийн тоо нь бүрэн комбинацийн тоотой адил биш.

### B6. Гүйцэтгэлийг баталгаажуулах

Доорх командаар шаардлагатай бүх PICT гаралтыг дахин үүсгэж, тестийн мөрийн тоог шалгана.

```bash
mkdir -p results

pict browser.model > results/browser-2way.txt
pict browser.model /o:3 > results/browser-3way.txt
pict transfer-nc.model > results/transfer-nc.txt
pict transfer.model > results/transfer.txt
pict transfer-neg.model > results/transfer-neg.txt
pict transfer-neg.model /o:3 > results/transfer-neg-3way.txt

for f in results/browser-2way.txt \
         results/browser-3way.txt \
         results/transfer-nc.txt \
         results/transfer.txt \
         results/transfer-neg.txt \
         results/transfer-neg-3way.txt
do
    printf '%s: ' "$f"
    awk 'NR > 1 {n++} END {print n+0}' "$f"
done
```

`results/pict-build.txt` нь тестийн мөрийн тооцоонд орохгүй; энэ файл PICT-ийн эх кодоос бүтээсэн commit болон хэрэглээний нотолгоо юм. PICT-ийн эх кодыг лабораторийн репод оруулахгүй.

### Дүгнэлт

Category-Partition арга нь оролтын ангилал, бизнесийн дүрэм, алдааны нөхцөлийг тодорхойлоход тохиромжтой. PICT нь параметрүүдийн хос болон гурвалсан хамралтыг системтэйгээр үүсгэдэг. Гараар боловсруулсан спецификаци нь хүлээгдэх үр дүнг илүү ойлгомжтой тодорхойлдог бол PICT нь комбинацийн хамралтыг нэмэгдүүлдэг. Хязгаарлалтгүй болон IF хязгаарлалттай загварын ялгаа нь боломжит тестийн комбинацад нөлөөлдөг. Сөрөг утгуудыг тэмдэглэх нь алдаатай нөхцөлүүдийг тусгаарлахад тусалдаг боловч oracle-ийг орлохгүй. Бодит тест кейс бүр setup, оролт, хүлээгдэх үр дүнтэй байх шаардлагатай. Greedy алгоритм нь практикт үр ашигтай ч хамгийн цөөн тестийн мөрийг баталгаатай гаргахгүй. Иймээс хоёр аргыг хамтад нь ашиглах нь тестийн чанар болон хамралтыг сайжруулдаг.
